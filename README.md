# GeeDrive API Server

This repository contains the GeeDrive fleet management API backend built with FastAPI and Supabase.

## Requirements

- Python 3.13 or newer
- `uv` package manager installed locally or globally
- A Supabase project with:
  - `SUPABASE_URL`
  - `SUPABASE_SERVICE_KEY` (service_role key)
- A secure `FLEET_API_KEY` with at least 32 characters
- A `.env` file in the repository root

> Note: The Supabase service role key is sensitive and must never be exposed in client-side code.

## Setup

1. Clone the repo and change into the project directory:

```bash
cd path/to/geedrive
```

2. Create a Python virtual environment with `uv` and activate it:

```bash
uv venv .venv
source .venv/bin/activate
```

3. Install dependencies from `pyproject.toml` into the active environment:

```bash
uv sync --active
```

> Tip: Run `uv sync --active` from the project root so it resolves `pyproject.toml` and `uv.lock` correctly.

4. Create a local `.env` from the example file:

```bash
cp .env.example .env
```

5. Edit `.env` and set the real values:

- `SUPABASE_URL` – your Supabase project API URL
- `SUPABASE_SERVICE_KEY` – your Supabase service role key
- `FLEET_API_KEY` – a secret 32+ character shared admin key
- `ALLOWED_ORIGIN` – comma-separated frontend origin(s)

Example `.env` values:

```env
SUPABASE_URL=https://your-project-ref.supabase.co
SUPABASE_SERVICE_KEY=sb_secret_yoursecretkey
FLEET_API_KEY=your-32+-character-secret-key
ALLOWED_ORIGIN=http://127.0.0.1:5173,http://localhost:5173
```

## Running the API Server

Use `uv` to run Uvicorn from the active environment:

```bash
uv run uvicorn api.main:app --host 127.0.0.1 --port 8000 --reload
```

The API should be available at:

- `http://127.0.0.1:8000`

## Testing

Run tests with `uv` to ensure the active environment is used:

```bash
uv run pytest
```

## Authentication

Most API endpoints require a Bearer token.

### Options

- Use the shared admin key: `FLEET_API_KEY`
- Or use a session token generated by the server at `/session`

### Header format

```http
Authorization: Bearer <FLEET_API_KEY>
```

> The `/health` endpoint does not require authentication.

## Important Environment Variables

- `SUPABASE_URL` — Supabase project URL
- `SUPABASE_SERVICE_KEY` — Supabase server-side service role key
- `FLEET_API_KEY` — shared API key for Bearer auth
- `ALLOWED_ORIGIN` — comma-separated list of allowed frontend origins

## Key API Endpoints

### Public / debug

- `GET /health` — health check, no auth required
- `POST /session` — returns a temporary session token
- `GET /debug-cors` — returns configured allowed origins
- `GET /debug-key` — returns debug info about the configured key length

### Authenticated endpoints

- `GET /dashboard` — fleet dashboard summary
- `GET /cars` — list cars
- `POST /cars` — register a new car
- `PATCH /cars/{car_id}` — update a car
- `PATCH /cars/{car_id}/decommission` — decommission a car
- `GET /cars/analytics` — car analytics
- `GET /cars/{plate_number}/last-mileage` — car mileage lookup
- `GET /drivers` — list drivers
- `GET /drivers/analytics` — driver analytics
- `POST /drivers` — register a driver with files
- `GET /drivers/check-nrc` — check NRC uniqueness
- `GET /drivers/{driver_id}/{doc_type}/signed-url` — get signed URL for driver document
- `POST /logs` — submit weekly log entry
- `GET /logs` — list weekly logs

## Notes

- The server loads `.env` using `pydantic-settings`.
- `ALLOWED_ORIGIN` can be set as a comma-separated string in `.env`.
- Session tokens are stored in memory and will be lost if the server restarts.

## Testing

If you want to run tests locally:

```bash
pytest
```
